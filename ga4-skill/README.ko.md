# GA4 스킬 (`ga4-skill`)

[English](./README.md) · **한국어**

[![skills.sh](https://skills.sh/b/ogaeng/ga4-skill)](https://skills.sh/ogaeng/ga4-skill)

**비개발자 마케터가 gcloud·SQL·JSON 없이 대화만으로 GA4에 연결하고, 이벤트 정의서를
관리하고, 데이터를 분석하게 하는 에이전트 스킬 4종.**

터미널도 개발 지식도 필요 없습니다. 사용자가 하는 일은 브라우저에서 로그인하고 평소 말로
질문하는 것뿐이며, 파일 배치·명령 실행·쿼리 작성은 전부 스킬이 대신합니다.

## 이렇게 쓰입니다

| 이렇게 말하면 | 이런 일이 벌어집니다 |
|---|---|
| "GA 연결해줘" | 브라우저 로그인 → 접근 가능한 속성 목록 제시 → 선택 저장 (5~10분, 1회) |
| "지난주 페이지뷰 알려줘" | Data API 조회 → 표로 정리된 답변 |
| "전환까지 어떤 행동을 하는지 분석해줘" | 퍼널·경로·중요도 분석을 조합한 리포트 |
| "이 정의서대로 수집되고 있어?" | 정의서 파싱 → 실측 대조 → 누락·미정의 이벤트 목록 |
| "지금 접속자 몇 명이야?" | 실시간 리포트 (최근 30분) |
| "GA 좀 봐줘" (모호함) | 현재 상태를 진단해 다음 할 일 2~3개를 선택지로 제안 |

## 스킬 4종은 이렇게 연결됩니다

```
        ┌──────────────────────────────────────────────┐
        │  ga4  (라우터)                                │
        │  모호·복합·처음 사용 요청을 받아                 │
        │  → 상태를 진단하고 순서에 맞게 위임               │
        └───────────────────┬──────────────────────────┘
                            │
   ┌────────────┐    ┌──────────────┐    ┌────────────┐
   │  ga-auth   │───▶│ ga-taxonomy  │───▶│   ga-use   │
   │    연결     │    │  정의서(선택)  │    │    분석     │
   │            │    │              │    │            │
   └────────────┘    └──────────────┘    └────────────┘
        │                   │                   │
   token.json          taxonomy.md          분석 결과
   config.json         (이벤트 사전)
        └────────── .ga4/ 디렉터리로 연결 ──────────┘
```

스킬끼리 코드를 import하지 않습니다. 프로젝트 로컬 `.ga4/` 디렉터리에 파일을 남겨 느슨하게
연결되므로, 각 스킬을 따로 쓸 수도 있습니다.

### `ga-auth` — 연결

GA4에 접속할 수 있게 만드는 단계. **1회만** 하면 됩니다.

- 관리자가 만든 데스크톱 OAuth 클라이언트로 로그인 — gcloud 불필요
- 접근 가능한 GA4 속성을 계정별로 묶어 제시하고, 선택한 속성을 저장
- 토큰 만료 시 자동 갱신, 계정 전환 시 재로그인 지원
- 마케터가 가장 많이 막히는 3대 함정(테스트 사용자 미등록, "확인되지 않은 앱" 경고,
  계정 전환)을 **미리** 짚어줌

### `ga-taxonomy` — 이벤트 정의서 (선택)

"우리가 설계한 대로 실제로 수집되고 있는가"를 확인하는 단계. 없어도 분석은 됩니다.

- **파싱** — Google Sheets URL 또는 로컬 xlsx·csv를 읽어 `taxonomy.json`·`taxonomy.md` 생성
- **열 자동 인식** — 헤더 이름과 순서가 템플릿과 달라도 별칭 사전으로 인식하고, 애매하면
  `--map`으로 보정
- **실측 대조** — *정의했는데 안 들어오는* 이벤트(구현 누락)와 *들어오는데 정의 안 된*
  이벤트(문서화 누락)를 분리해 보고하고, 둘 사이의 오타 가능성을 짚어줌
- **초안 역산** — 정의서가 아예 없으면 실제 수집 중인 데이터에서 CSV 초안을 만들어줌

### `ga-use` — 분석

자연어 질문을 GA4 Data API 리포트로 바꿔 답하는 단계. **가장 자주 쓰는 스킬**입니다.

| 리포트 유형 | 쓰는 때 |
|---|---|
| 기본 리포트 | 지표 × 차원 조합, Top-N, 기간 비교, 필터 |
| 실시간 | "지금 접속자", "방금 발생한 이벤트" (최근 30분) |
| 피벗 | "국가 × 디바이스별" 같은 교차표 |
| 코호트 | "6월 가입자가 주차별로 얼마나 재방문하나" (리텐션) |
| 퍼널 | "조회 → 장바구니 → 구매" 단계별 전환·이탈 |
| 메타데이터 | 이 속성에서 실제로 쓸 수 있는 차원·지표 조회 |

복합 질문(전환 분석, 경로·여정, 성과 요약, 변화 원인 진단, 콘텐츠 성과, 행동 중요도 비교)은
[`analysis-recipes.md`](./skills/ga-use/references/analysis-recipes.md)의 레시피에 따라
여러 쿼리를 계획적으로 조합합니다.

## 설치

```bash
npx skills add ogaeng/ga4-skill
```

현재 프로젝트에 설치됩니다. 유용한 변형:

| 명령 | 효과 |
|---|---|
| `npx skills add ogaeng/ga4-skill -g` | 전역 설치 (모든 프로젝트에서 사용) |
| `npx skills add ogaeng/ga4-skill -a claude-code` | 특정 에이전트에만 설치 |
| `npx skills list` | 설치된 스킬 조회 |
| `npx skills update` | 최신 릴리스로 업데이트 |
| `npx skills remove ogaeng/ga4-skill` | 제거 |

Claude Code, Codex, Cursor, Gemini CLI 등
[Agent Skills CLI](https://github.com/vercel-labs/skills)가 지원하는 에이전트에서 동작합니다.
네 스킬은 한 세트로 설계됐으므로 전부 설치하세요.

## 준비

설치만으로는 부족합니다. 구글이 분석 데이터를 읽으려면 OAuth 클라이언트를 요구하기
때문입니다. 두 가지 역할이 각각 1회씩 준비합니다.

### 1단계 — 관리자 (조직당 1회)

Google Cloud 프로젝트 편집 권한을 가진 사람이 **데스크톱 OAuth 클라이언트**를 만들어
다운로드한 JSON을 사용자들에게 전달합니다. 약 5분이면 되고 다시 할 일은 없습니다:
Analytics API 2개 사용 설정 → 동의 화면 구성 → 데스크톱 클라이언트 생성 → JSON 다운로드.

**전체 절차:
[`admin-setup-guide.md`](./skills/ga-auth/references/admin-setup-guide.md)** — 대부분이
놓치는 테스트 사용자 등록 단계까지 포함돼 있습니다.

에이전트에게 *"GA4 OAuth 클라이언트 설정해줘"*라고 요청하면 `ga-auth`가 대화로 안내합니다.

### 2단계 — 각 사용자 (1회)

1단계에서 받은 JSON을 프로젝트에 둡니다:

```bash
mkdir -p .ga4
cp ~/Downloads/client_secret_XXXX.json .ga4/oauth_client.json
```

그리고 에이전트에게 이렇게 말합니다:

> **"GA 연결해줘"** / **"Connect Google Analytics"**

파이썬 환경을 만들고, 브라우저 로그인을 열고, 접근 가능한 GA4 속성을 제시한 뒤 선택을
저장합니다. 이후부터 바로 질문하면 됩니다.

> 데스크톱 OAuth 클라이언트의 `client_secret`은 진짜 비밀이 아니므로(데스크톱 앱은 비밀을
> 숨길 수 없습니다) 같은 파일을 조직 구성원 모두에게 나눠줘도 됩니다.

### 요구 사항

- **Python 3.10+** — 첫 사용 시 `.ga4/venv`에 격리된 가상환경이 생성됩니다(에이전트가 처리).
- GA4 속성에 **뷰어 이상** 권한이 있는 구글 계정.

## 생성되는 파일

모든 파일은 프로젝트 로컬 `.ga4/` 디렉터리에 들어갑니다(`GA4_DIR` 환경변수로 변경 가능).

> ⚠️ **`.ga4/`를 `.gitignore`에 추가하세요** — 인증 토큰이 들어 있습니다.

| 파일 | 생성 주체 | 용도 |
|---|---|---|
| `oauth_client.json` | 사용자 (2단계) | 조직의 OAuth 클라이언트 |
| `token.json`, `config.json` | ga-auth | 로그인 토큰과 선택한 속성 |
| `taxonomy.json`, `taxonomy.md`, … | ga-taxonomy | 파싱된 이벤트 정의서 |
| `venv/` | 공용 | 격리된 파이썬 환경 |

## 문제 해결

**"액세스 차단됨: 앱이 테스트 모드입니다"** — 로그인하려는 계정이 동의 화면의 테스트
사용자로 등록되지 않았습니다. 관리자가 **OAuth 동의 화면 → 테스트 사용자**에 추가하면
됩니다. (Workspace 조직에서 내부(Internal) 동의 화면을 쓰면 불필요합니다.)

**"Google에서 확인하지 않은 앱입니다"** — 직접 만든 미검증 클라이언트에서는 정상입니다.
**고급 → 계속**을 선택하세요.

**스크립트가 파이썬 모듈 없음으로 실패** — 에이전트에게 상태 점검을 요청하세요. 무엇이
빠졌는지 알려주고 직접 설치합니다.

**에이전트가 스킬을 쓰지 않음** — 스킬 이름을 직접 부르세요: *"ga-use 스킬로 …해줘"*.

## 참고

- 설치 위치에 구애받지 않습니다. 스킬 문서는 `{SKILLS_DIR}` 플레이스홀더를 쓰고 스크립트는
  형제 스킬 경로를 자기 설치 위치에서 역산하므로, 에이전트가 어디에 설치하든
  (`.claude/skills`, `.agents/skills` 등) 동작합니다. **Claude Code**에서 가장 많이
  검증했습니다.
- 모든 API 접근은 **읽기 전용**입니다(`analytics.readonly` + `spreadsheets.readonly`).
  Google Analytics에 무언가를 쓰는 일은 없습니다.
- 에이전트는 사용자가 쓰는 언어로 답하며, 오류 힌트도 그대로 붙여넣지 않고 풀어서
  설명합니다.
